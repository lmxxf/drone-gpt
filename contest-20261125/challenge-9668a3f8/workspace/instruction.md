# 给聚变加热器一个更聪明的控制器

一团已经开始聚变的等离子体，还需要多少外部加热？答案会随着反应本身改变：温度升高，聚变加快，留在燃料中的 α 粒子又会继续加热燃料；与此同时，输运和辐射不断把热带走。加热器面对的是一套会自己发热、也会不断散热的系统。

未来装置需要在这样的反馈中稳定运行。加热太少，可能完不成预定产出；加热太多，又会浪费能量。更棘手的是，诊断有延迟和噪声，杂质与初始状态也不会每次完全相同。控制器必须根据已经收到的信号，决定下一步怎样供热。

**你的任务是为托卡马克设计一个反馈控制器：在规定扰动下完成同一份聚变能量交付、保留末态热储能，并尽量减少整个运行段的供热。**

## 1. 科学目标：既完成任务，也把热量用得更有效

### 1.1 两路加热，是两种影响等离子体的方式

等离子体的电子和离子可以有不同温度。热量先交给谁、沉积在哪里，会影响它们之间的能量交换以及从核心到边缘的温度分布。氘氚反应取决于离子的状态；加热电子也可能通过交换能量间接改变反应。因此，总功率相同，并不意味着两种加热分配有相同的效果。

你可以调节一路通用热源和一路电子回旋加热。两路都有功率、变化速度和响应延迟限制。一次操作的影响还会延续到未来：当前节省的热量可能需要稍后补回，提前供热也可能通过聚变自加热改变后续需求。需要优化的是完整的运行轨迹。

### 1.2 什么才算有价值的节能？

让装置少产出一些，当然容易少用一些热。本题固定所有场景都要完成的累计聚变产出，并限制聚变功率波形的偏离；运行结束时还要留下足够的热能，避免把下一段运行的负担藏在终点之后。评价同时计入外部执行器和维持规定边缘温度的正向热输入。

在这些共同条件下，比较最不利场景的供热，才能检验控制器是否更有效地利用了加热分配、时序和热反馈。恒功率参考控制器提供可运行的起点，在部分扰动下尚未完成产出要求；让它先达标，也是任务的一部分。

### 1.3 你将在什么数值实验中工作？

TORAX 计算电子、离子的径向热输运，Gym-TORAX 提供控制交互接口。本题固定几何、密度、电流和边缘条件，让研究集中在热控制。你可以使用传统反馈、预测控制、离线优化或带记忆的学习策略；最终交付一个每 0.5 秒输出两路命令的 `controller.onnx`。[TORAX 研究](https://arxiv.org/abs/2406.06718)

一个成功的结果，是在明确模型和共同任务下可重放的节能控制策略，可供后续脉冲规划与其他输运模型检验。这里计算的是核心热模型中的供热，不是整机耗电；成绩不能直接换算成电站净发电量。

## 2. 受控对象与约束（Constraints）

统一条件来自随包的 `torax-config.json`、`case.json` 和公开几何文件；评估器不会接受候选自行替换物理模型。

| 条件 | 本题定义 |
|---|---|
| 几何与场强 | 公开 `iterhybrid.mat2cols` CHEASE 几何；R=6.2 m、a=2.0 m、B₀=5.3 T |
| 总电流边界 | Iₚ=10.5 MA；原生 j 初始化，current_profile_nu=0.5，完整电流背景不演化 |
| 密度背景 | ρ=0/0.9/1 上 nₑ=8/6.2/2.5×10¹⁹ m⁻³，径向插值，所有场景固定 |
| 燃料 | 氘、氚各占主离子的一半；初始有效电荷 Z_eff=1.6 |
| 运行段 | 30 s；控制间隔 Δt=0.5 s |
| 初始温度 | 公开示例径向温度剖面，轴区约 15 keV；每个场景统一乘以公开范围内的扰动因子 |
| 边缘条件 | 原生规定基座模型（近边缘的规定温度区）；Tᵢ=Tₑ=4.5 keV、基座位置 ρ=0.9、电子密度 0.62×10²⁰ m⁻³ |
| 输运 | 原生 QLKNN_7_11 与规定内外区补丁；不裁剪 QLKNN 输入来伪造模型有效性 |
| 可改变的量 | 两路吸收加热功率：Gaussian 通用热源 P_G 和原生 ECRH 热源 P_E |
| 不能改变的量 | 燃料比例、密度/电流背景、杂质扰动、几何、基座、沉积位置与宽度、数值求解器和输运模型 |

ρ 是模型的归一化径向坐标。通用热源用原生 Gaussian 加热入口表示，其电子加热比例固定为 0.66；它不是完整中性束沉积、快离子和电流驱动模型。ECRH 使用 TORAX 的原生电子回旋加热及关联电流驱动入口。电流背景固定，因此这里不计算 ECRH/ECCD 改变电流剖面的控制收益，也不评价 bootstrap 电流自洽演化；外部维持这些背景的耗电未计入。

| 执行器 | 范围 | 初始功率 | 沉积中心 / 宽度 | 最大变化速度 |
|---|---:|---:|---:|---:|
| P_G | 0–33 MW | 28 MW | ρ=0.25 / 0.25 | 4 MW/s |
| P_E | 0–20 MW | 15 MW | ρ=0.15 / 0.15 | 4 MW/s |

每个控制时刻，两条命令相对上一条命令的变化均不能超过 2 MW。命令排队一个控制间隔后进入执行器，原生接口在该间隔内把功率从旧值线性变化到新值。最开始的一个间隔保持初始功率；最后一次尚未到达执行器的命令不产生提前收益。越界动作不会被自动裁剪后继续计分。

## 3. 从公开参考控制器出发

`/app/reference/controller.onnx` 始终保持 P_G=28 MW、P_E=15 MW。这个简单起点让你能先运行一次完整模拟，再观察反馈策略怎样改变温度、聚变功率和供热。两路参考功率都低于执行器上限，留有应对扰动的余量。 这份恒功率控制器可以完整运行，但在规定扰动下尚未满足全部产出要求；它是理解接口与改进控制的起点。

所有控制器承担同一个运行任务。目标聚变功率波形、最低累计产出 Q_req 和末态参考热能 W_reference(T) 均由名义场景中的恒功率策略定义：400 个径向单元、0.0025 s 原生步长，温度初态倍率为 1，Z_eff=1.6，不施加杂质事件。

这些固定目标保存在 `/app/reference/baseline.json`。功率波形每 0.5 s 采样；Q_req 对名义运行的全部原生接受步作梯形积分，约为 3.34 GJ；W_reference(T) 取名义末态，约为 185.53 MJ。比较使用文件中的完整数值。每个扰动场景都需满足同一产出和储能要求，控制收益才能来自更有效的供热。

你可以探索固定时序、PI 控制、有记忆的神经网络，或把离线优化结果蒸馏成满足提交接口的策略。求解方法开放；正式运行时每一步只能使用已经到达的观测及控制器自己的记忆。

公开资源包含从头运行模拟器所需的配置、几何和模型。训练与搜索可使用自己产生的模拟轨迹。

## 4. 控制器的输入与输出（Input / Output）

最终产物是 **`/app/controller.onnx`**，只包含标准 ONNX 计算图。评估器不执行候选的 Python、共享库、文件读取或自定义算子。

计算图只有一个输入 `float32[1,48]`，一个输出 `float32[1,34]`。输入最后 32 个数是控制器记忆，首次全为零；输出前 2 个数是本时刻两路功率命令，单位 MW，后 32 个数是下一时刻记忆。记忆必须保持在 [-100,100]。

| 输入下标 | 内容 | 单位 / 规则 |
|---|---|---|
| 0–1 | 当前控制时刻、Δt | s；Δt=0.5 |
| 2 | 聚变功率 | MW |
| 3 | 等离子体总热能 | MJ |
| 4–5 | 最内径向网格的 Tₑ、Tᵢ | keV；这是有限网格值，不是额外拟合出的磁轴温度 |
| 6 | 最内网格电子密度 | 10²⁰ m⁻³ |
| 7–9 | q_min、q95、β_N | 原生诊断定义 |
| 10 | 沿线平均电子密度 | 10²⁰ m⁻³ |
| 11 | 本时刻规定的目标聚变功率 | MW；不提供未来目标或未来扰动 |
| 12–13 | 当前执行器端的两路功率 | MW |
| 14–15 | 上一次发出的两路命令 | MW |
| 16–47 | 上一次输出的控制器记忆 | 首次为 0 |

第 2–10 项延迟一个控制间隔：时刻 t_k 收到 t_{k−1} 的模型诊断；首次使用初始状态。每个通道乘以独立的 `1+η`，η 由标准正态截到 ±3 倍标准差后生成。聚变功率和热能的相对标准差为 1%，温度与两项密度为 0.5%，q 与 β_N 为 0.1%。这是公开的理想化诊断噪声模型，不声称来自某台装置的标定数据。

图须使用 ONNX opset 18、IR≤10，大小≤4 MiB、节点≤512；所有中间张量具有静态正维度，单张量≤65536 元素、单轴≤4096。禁止循环、条件子图、自定义域、随机算子、外部权重文件和训练图。允许算子清单在 `controller.py` 中。推理在独立进程中执行，每次在线调用限 1 s，超时立即终止；每条轨迹的图加载另限 20 s。动作、记忆和观测必须有限。没有场景编号、种子、原生模拟器对象、未经延迟的状态或未来扰动输入。

得到第一个合法计算图后就写入 `controller.onnx`，之后用更好的图替换。替换时先写临时文件再改名。解题时限结束后，正式评估只读取这个文件，复算不读取你的日志或自报性能。

## 5. 如何复算与打分？

### 5.1 先执行同一组物理场景

公开开发集合有 4 个固定种子；正式集合有 16 个在发布前固定并留存哈希的种子。两者使用完全相同的公开分布，各候选使用相同的物理扰动和观测噪声。正式集合不改变运行规则。

| 扰动 | 公开生成规则 |
|---|---|
| 初始温度剖面 | 同时乘以 U[0.98,1.02] 的因子 |
| 事件开始 | t_event∼U[8,16] s |
| 有效电荷 | 从 1.6 线性变化到 U[1.55,1.75]，变化持续 2 s |

上述三个随机变量按 `eval.py` 的 PCG64 顺序生成。它们是用于比较闭环鲁棒性的规定情景，不是未来事件的预测分布。控制器只看到过去的诊断，不能直接读取事件参数。

每个场景分别用 200 个径向单元、0.005 s 原生步长，以及 400 个径向单元、0.0025 s 原生步长复算。控制器每 0.5 s 调用一次；同一条线性功率坡道由原生动作入口在 0.005/0.0025 s 接受步边界送入，逐步保留状态。关闭自适应步长，每个原生接受步必须真实推进到请求时间，非线性求解器状态必须为 0；保留旧状态、提前结束或不收敛不能作为成功轨迹。

QLKNN 的实际输入由上游预处理器与模型给出的训练范围检查；检查初始状态及每个原生接受步，其作用区域中的输入越出训练边界时，该候选标为 `candidate_unresolved`。这不证明两个接受步之间、非线性求解器的迭代试探状态或真实装置轨迹都落在有效范围内。落在输入矩形范围内也不意味着模型已经覆盖真实燃烧等离子体的一切物理。

### 5.2 维持热源与规定的运行范围

以下要求在每个场景的两档轨迹上同时检查。数值有效但未全部达标的控制器仍有进展分。

| 要求 | 固定门槛 | 作用 |
|---|---|---|
| 聚变总产出 | 每个场景、每档网格 ∫P_fusion(t)dt≥Q_req | 固定共同交付量，不允许少产能换节能 |
| 聚变功率总体跟踪 | 全段相对误差 RMS≤10% | 限制运行波形偏离；总产出另有独立约束 |
| 聚变功率峰值误差 | 控制采样点最大相对误差≤25% | 限制明显跌落或过冲 |
| 压强 | β_N≤2.8 | 限制归一化压强；不是完整稳定极限 |
| 温度 | 任意径向网格的 Tₑ、Tᵢ≤35 keV | 限制靠极端高温运行换取收益 |
| 终端热能 | W(T)≥0.98 W_reference(T) | 避免耗尽热储能、把维持运行的成本挪到运行段之后 |

功率 RMS 用 0.5 s 控制采样点的梯形积分除以 30 s 后开方；所有约束在两档分辨率、所有场景同时检查。固定背景必须满足 q_min≥1、q95≥3、Greenwald 比≤1，作为出题配置准入条件，不计控制器违规。它们保留为观测/数值诊断，控制器不负责修复不可控背景。β_N 与温度范围在每个原生 0.005/0.0025 s 接受步检查，终端热能在 30 s 检查；这些离散检查不是连续时间安全证明。

10% 跟踪走廊允许调整产出的时间分布，但不允许降低全段聚变能量交付量。总产出在每个原生接受步上用梯形积分计算。终端储能约束另行防止透支热能。

### 5.3 达标后比较最不利外部热能

每条轨迹先读取 TORAX 原生辅助与欧姆累计热能，再计入维持规定 pedestal 温度的原生正向净供热：

```text
E_ext = E_external_total(T) − E_external_total(0)
      = 原生梯形累计的辅助加热 + 欧姆加热
E_ped+ = Σ[k=1..N] max(P_pedestal(t_k), 0) × (t_k−t_(k−1))
E_s,r = E_ext + E_ped+
ΔE_s  = abs(E_s,coarse − E_s,fine)
J     = max_s [max(E_s,coarse, E_s,fine) + ΔE_s]
```

P_pedestal 是离子、电子基座源项在全体积积分后的合计净功率，通过上游固定温度边界的 `apply_adaptive_source` 与 `cell_integration` 提取。其正项按本题原生 theta=1 的接受步右端点计量，负向散热不抵扣；否则候选可能少开执行器、却借用未计费的边界热源。t=0 的惩罚源只是初始状态诊断，不是已经执行的隐式步；包含 t=0 的梯形供热积分也单独报告，用于检查刚性初始松弛。辅助/欧姆热采用上游梯形累计口径；结果同时报告右端点积分与该口径的差异。维持固定电流和密度背景的装置功耗仍不在模型内。初始与最后实际执行区间都计入。双网格差值补偿是本题的比较规则，不是连续方程误差上界。

上游 `P_external_total` 采用注入功率口径；本题两路热源全吸收，因此它与辅助吸收功率加欧姆功率相等。评估器逐原生接受步检查这一等式，并核对累计能量与功率梯形积分；吸收口径发生变化时拒绝套用现有评分定义。

为保证两档计算可比较，两档供热能量差须≤2% J_ref；聚变功率在共同的 61 个控制采样点上的最大差须≤参考功率波形峰值的 2%；q_min、q95、β_N 的极值差均须≤0.02。不满足这些精度条件的轨迹记为未解析。J_ref 是同一场景集合、同一规则下恒功率参考策略的供热目标值；开发与正式集合分别使用各自的固定值，见 `reference/baseline.json`。双网格差值用于比较有限分辨率的结果，不构成连续方程的严格误差界。

完整有效轨迹的分数 S∈[0,1]：

```text
全部约束通过：S = 0.5 + 0.5 × J_ref / (J_ref + J)
存在约束违反：S = 0.5 × exp(−Σ v_i²)，严格小于 0.5
```

v_i 是跨场景与两档分辨率的最大归一化超限。聚变交付亏损的归一化量为 max(0,1−Q/Q_req)/0.02；这里 0.02 仅是进展分尺度，合格结果不允许亏损。其余归一化尺度依次为功率 RMS 0.1、峰值 0.25、β_N 2.8、温度 35 keV、终端热能亏损 0.02；`eval.py` 给出唯一实现。达标且 J=J_ref 时，公式给出 0.75；供热目标 J 越小，分数越高。

文件缺失、非法图或越界动作的成绩为 0；物理不收敛、模型越界或数值精度不足的成绩也为 0，但状态为 `candidate_unresolved`。缺少可信镜像、参考校准或验收证据时返回 `evaluator_error=1`，不能把它解释成候选的科学失败。

## 6. 开始运行与完成条件（Completion criteria）

资源入口是 `environment/resources.yaml`，在镜像中对应 `/app/resources.yaml`；公开物理配置、开发评估器、参考图与数据来源都列在其中。完成本题需要在时限内留下符合第 4 节接口的 `/app/controller.onnx`，其物理性能由第 5 节完整复算决定。

解题目录为 `/app`，提供原生 TORAX、Gym-TORAX、ONNX、ONNX Runtime，以及配置、几何、开发评估器和参考图。解题可用 32 CPU、128 GiB 内存，不要求 GPU；固定镜像与运行时限见 `task.toml`。完整评估的时间预算见 `task.toml`。

```bash
cp /app/reference/controller.onnx /app/controller.onnx
/opt/t0/env/bin/python -I /app/eval.py /app/controller.onnx \
  --resources /app --development \
  --workdir /app/check-001 --reward-dir /app/check-001-reward
```

每次调用使用新的空目录。公开程序会保留轨迹、原生输出、命令、输运范围检查和失败原因。`background.zip` 中有相同版本的代码、数据来源和问题定义，便于检查单位、延迟和评分。

正式评估使用独立干净的可信环境，只接收 `controller.onnx`。求解容器中的模型、参考文件、评分程序或环境修改，不会进入正式计算。优化的对象是控制器本身。
